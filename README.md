# وب‌سایت دکتر بهنام وزیریان

وب‌سایت دکتر بهنام وزیریان، دامپزشک و رزیدنت جراحی؛ فارسی و راست‌به‌چپ با طراحی Liquid Glass، تصویر دکتر، مدل‌های سه‌بعدی واقعی و رابط سازگار با موبایل.

## اجرا

پیش‌نیاز: **Node.js 24 یا جدیدتر** و npm. فونت وزیرمتن، مدل سه‌بعدی و تصویر همگی محلی هستند و در زمان اجرا به CDN یا کلید API نیاز ندارند.

```bash
cd /workspace/my-website2
npm ci
npm run dev
```

دستور توسعه هم‌زمان Vite روی پورت `5173` و API روی پورت `3001` را اجرا می‌کند. مسیرهای `/api` از طریق Vite به سرور هدایت می‌شوند.

برای نسخه تولید:

```bash
npm run build
PORT=3001 npm start
```

سرور Node هم فایل‌های `dist` و هم API را ارائه می‌کند. برای اینترنت عمومی، از reverse proxy با HTTPS استفاده کنید. پروکسی باید `Host` اصلی را حفظ کرده و `X-Forwarded-Proto: https` را ارسال کند تا کوکی نشست با ویژگی `Secure` تنظیم شود. اگر مبدأ خارجی متفاوت است، `APP_ORIGIN` را با مبدأ دقیق عمومی تنظیم کنید.

## انتشار آزمایشی روی Render

فایل `render.yaml` اجرای ساخت و راه‌اندازی روی پلن رایگان Render را تعریف می‌کند. پس از قرار گرفتن این فایل در مخزن، صفحه `https://render.com/deploy?repo=https://github.com/golozar689-debug/my-website2` فرایند انتشار را از روی همین تنظیمات آغاز می‌کند. ورود به حساب Render و مجوز دسترسی به مخزن لازم است؛ این نشانی، صفحه راه‌اندازی است و آدرس سایت منتشرشده نیست. پس از موفقیت انتشار، Render آدرس عمومی سرویس را ارائه می‌کند.

این پلن فقط برای نمایش و آزمایش مناسب است: دیسک پایدار ندارد و حساب‌ها، نوبت‌ها و نظرها ممکن است پس از راه‌اندازی مجدد یا انتشار بعدی پاک شوند. برای استفاده واقعی، پایگاه داده روی دیسک پایدار یا سرویس پایگاه داده مستقل لازم است. تنظیم پلن رایگان هیچ سرویس پولی یا دیسک پولی ایجاد نمی‌کند.

## امکانات سایت

- ثبت‌نام، ورود، خروج و بازیابی نشست با کوکی HttpOnly؛ رمزها با scrypt هش می‌شوند.
- تقویم شمسی و ساعت‌های منطقه زمانی تهران؛ انتخاب روز، ساعت و نوع مراجعه.
- ذخیره درخواست نوبت، جلوگیری از رزرو هم‌زمان یک ساعت و لغو درخواست از حساب کاربری.
- ثبت امتیاز و نظر توسط کاربر واردشده و نمایش تجربه‌های ثبت‌شده؛ بدون نظر یا آمار ساختگی.
- پنل مدیر در مسیر `/admin` برای مشاهده و جست‌وجوی کاربران، مسدودسازی حساب، تأیید و لغو نوبت، مدیریت نمایش نظرها و مشاهده رویدادهای مدیریتی.
- SQLite در `.data/site.sqlite`؛ بدون سرویس پایگاه داده جداگانه. ماندگاری اطلاعات به ماندگاری دیسک میزبان بستگی دارد.
- المان‌های شیشه‌ای Three.js با بازتاب محلی، پارالاکس و حرکت شناور؛ جایگزین CSS در دستگاه‌های فاقد WebGL و احترام به تنظیم کاهش حرکت.
- پنجره‌های قابل استفاده با صفحه‌کلید، مدیریت فوکوس و منوی موبایل.

## وضعیت برنامه مراجعه

**زمان‌ها نمونه هستند.** این موضوع در انتخاب زمان، ثبت درخواست، حساب کاربری و پرسش‌های متداول مشخص شده است. نمونه فعلی شنبه تا پنجشنبه ساعت ۱۶:۰۰ تا ۱۹:۳۰، با فاصله نیم‌ساعته و بازه رزرو ۶۰روزه است. درخواست‌ها ابتدا وضعیت «در انتظار تأیید مطب» دارند؛ مدیر می‌تواند آن‌ها را در سامانه تأیید یا لغو کند. وضعیت تأیید در حساب مراجعه‌کننده نمایش داده می‌شود. پیش از استفاده عمومی، برنامه واقعی حضور باید توسط مرکز دامپزشکی تأیید و جایگزین شود.

پیش از راه‌اندازی عمومی باید ساعت واقعی حضور، آدرس و اطلاعات تماس توسط مطب تأیید شود. پیامک، ایمیل تأیید، بازیابی رمز و پرداخت در این نسخه پیاده‌سازی نشده‌اند. نوع «مشاوره دامپزشکی» صرفاً ثبت درخواست هماهنگی است و تماس تصویری برقرار نمی‌کند. حساب‌ها ایمیل‌تأییدشده نیستند و ثبت نظر به معنی اثبات مراجعه نیست.

## ورود مالک سایت به پنل مدیریت

مالکیت فنی سرویس با حساب Render و Workspace‌ای است که سرویس در آن ساخته شده است. پنل مدیر داخل سایت، دسترسی جداگانه برای مدیریت کاربران و درخواست‌ها دارد.

در پیکربندی Render، `ADMIN_EMAIL` برای ایمیل انتخاب‌شده مالک تنظیم شده و `ADMIN_PASSWORD` با `generateValue: true` به‌صورت تصادفی توسط خود Render تولید می‌شود. هیچ رمز مدیریتی در GitHub یا این راهنما قرار ندارد.

پس از اعمال نسخه جدید Blueprint و موفق شدن انتشار:

1. سرویس `dr-vazirian-vet` را در Render باز کنید و وارد بخش **Environment** شوید.
2. مقدار `ADMIN_PASSWORD` را فقط در همان حساب Render مشاهده یا کپی کنید. آن را در گفتگو، گزارش خطا یا GitHub قرار ندهید. اگر این متغیر هنوز وجود ندارد، Blueprint را با آخرین commit همگام کنید؛ یا در Environment آن را با یک رمز تصادفی قوی و دست‌کم ۱۲ نویسه ایجاد و سرویس را مجدداً منتشر کنید.
3. انتهای آدرس عمومی سایت، `/admin` اضافه کنید.
4. با ایمیل `ADMIN_EMAIL` و رمز `ADMIN_PASSWORD` وارد شوید. برای مدیر، ثبت‌نام عمومی لازم نیست؛ حساب از تنظیمات امن سمت سرور ساخته می‌شود.

وجود ایمیل در ثبت‌نام یا ارسال نقش از مرورگر، کاربر را مدیر نمی‌کند. تنها تنظیم هم‌زمان دو متغیر معتبر در سرور، مالک را مشخص می‌کند. اگر حسابی از قبل با ایمیل مالک وجود داشته باشد، هنگام پیکربندی، رمز آن با رمز مدیریتی تنظیم می‌شود و نشست‌های قبلی آن باطل می‌شوند. راه‌اندازی مجدد با همان تنظیمات، نشست معتبر مدیر را باطل نمی‌کند. تغییر رمز یا انتقال مالکیت به ایمیلی دیگر، نشست‌های قبلی مرتبط را باطل می‌کند. برای انتقال مالکیت، هم ایمیل و هم رمز مدیریتی را تغییر دهید؛ استفاده دوباره از رمز مالک قبلی در انتقال مالکیت پذیرفته نمی‌شود. در این نسخه تنها یک مالک پیکربندی‌شده وجود دارد.

مدیر نام و ایمیل کاربران، زمان ثبت حساب، نوبت‌ها، شماره همراه ثبت‌شده برای نوبت و نظرها را می‌بیند. رمز عبور، هش رمز و توکن نشست کاربران از API یا پنل قابل مشاهده نیست. پنل امکان ورود مخفیانه به حساب دیگران ندارد. مسدودسازی کاربر، نشست‌های فعال او را باطل می‌کند و تا رفع مسدودی امکان ورود مجدد ندارد. مخفی کردن نظر، آن را از نمایش عمومی خارج می‌کند و مدیر می‌تواند دوباره نمایش دهد. رویدادهای مدیریتی بدون ذخیره رمز یا توکن ثبت می‌شوند.

برای توسعه محلی، متغیرهای مدیر را فقط در محیط محلی یا فایل `.env` نادیده‌گرفته‌شده توسط Git قرار دهید؛ سپس می‌توانید از `node --env-file=.env server/index.mjs` استفاده کنید. فایل `.env` خودکار توسط `npm start` خوانده نمی‌شود. آزمون‌ها از تنظیمات و پایگاه جداگانه استفاده می‌کنند.

**پلن رایگان Render دیسک پایدار ندارد.** پس از بازسازی سرویس، حساب مدیر از متغیرهای محیط دوباره ساخته می‌شود، اما داده‌های قبلی کاربران، نوبت‌ها، نظرها و رویدادها ممکن است از بین بروند. برای استفاده واقعی، دیسک پایدار یا پایگاه داده مستقل نیاز است؛ این تغییر هیچ پلن پولی را فعال نمی‌کند. پس از اتصال دیسک پایدار، متغیر `DB_PATH` را به مسیر فایل پایگاه روی همان دیسک تنظیم کنید؛ برای مثال `/var/data/site.sqlite` فقط وقتی دیسک در `/var/data` متصل شده است.

پایگاه داده حاوی اطلاعات حساب و شماره همراه است؛ `.data` در Git قرار نمی‌گیرد. برای استقرار عمومی، دسترسی فایل و پشتیبان‌گیری امن را تنظیم کنید. چند نسخه سرور نباید هر کدام یک دیسک محلی مستقل برای یک برنامه رزرو مشترک داشته باشند.

## آزمون‌ها

```bash
npm test
npm run build
```

آزمون‌های سرور با پایگاه داده جداگانه، ثبت‌نام و ورود، نشست، CSRF، اعتبارسنجی، رقابت رزرو هم‌زمان، لغو، نظرها، ماندگاری داده، امنیت فایل‌های استاتیک و مرز دسترسی مدیریت را بررسی می‌کنند. هیچ داده آزمایشی در پایگاه سایت درج نمی‌کنند.

فایل‌های اصلی: `src/App.jsx` رابط صفحه، `src/styles.css` طراحی، `src/components/GlassScene.jsx` صحنه سه‌بعدی، `src/components/AccountDialogs.jsx` حساب کاربری، `src/components/AdminDashboard.jsx` و `src/admin.css` پنل مدیریت و `server/index.mjs` سرور و پایگاه داده.
